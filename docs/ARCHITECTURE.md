## 组件说明

| 组件 | 作用 | 归属层 |
|------|------|--------|
| ai-svc | 推理业务 API，对外服务 | app（业务面） |
| vLLM/model | 模型推理服务（模拟真实的 AI 服务对象）| app |
| prometheus/grafana/loki | 指标、可视化、日志 | monitoring（可观测面）|
| alertmanager | 告警分发 | monitoring |
| aiops-assistant | LLM 运维助手：查指标、拉日志、分析根因 | aiops（智能面）|
| LLM API + RAG | 云端大模型 + 运维知识库检索 | aiops |

## 数据流（核心流程）
1. 用户/测试流量打到 `ai-svc` → 调用了 `vLLM` 推理 → 返回结果。
2. 整个过程的指标/日志被 Prometheus/Loki 采集。
3. 当某指标触发告警（如 P99 延迟升高）→ Alertmanager 发出 Webhook。
4. `aiops-assistant` 收到告警 → 自动查询关联指标 + 拉取近段时间日志 + 检索运维知识库(RAG) →
   交给 LLM 生成「根因推断 + 处置建议」→ 推送给人 / 告知自愈动作。
5. AI 给出的建议可在人审批后落为 kubectl 操作（可选自愈闭环）。

## 设计思路
- **运维对象是 AI 服务 + 运维手段由 AI 驱动** → 两端都靠 AI。
- 三层解耦：业务面(app)、可观测面(monitoring)、智能面(aiops)，职责清晰可扩展。
- 贴合真实 SRE/AIOps 趋势：告警响应正从「人看日志」转向「LLM + 上下文」。
